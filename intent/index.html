The harness behind it

ThoughtSignal is the harness I am building in my own time: a Chief-of-Staff-style AI harness with one human-facing agent. The front agent reconciles your intent and dispatches. Workers are role-scoped and run in isolated copies, validators gate every push, and merges happen only on my word. Backpass reads each session's record and proposes changes to the harness, and I approve them. One base map serves every tool.

How I work with agents

"Managing a complex AI agentic bot system is sort of like managing a contract with different vendors."

Each agent is a vendor with a brief, a scope and a deliverable. I write down what I want, check what comes back, and decide what happens when it goes wrong. Every task starts as a brief with the intent, the rules and a definition of done. Work leaves a phase only when its check passes, and a claim with no passing check is "in trial", not a feature.

The method comes from ICM by Jake Van Clief (a short map and numbered stages), Kun Chen's agent stack (one dispatcher, throwaway copies of the code, a gate before every push) and Matt Pocock's skills (capture the intent before the spec).

What the crew may do, and what waits for me

A good contractor can use the tools on site without asking, asks before knocking down a wall, and never does some things whoever asks. My agents work the same way.

On its own

  • Read files and write code, in a throwaway copy of the repo, one per task.
  • Run tests, linters and a browser to check its own work.
  • Research, and write reports and drafts for me to read.
  • Push its own branch and open a pull request.

Waits for me

  • Merging, and any push to the main branch.
  • Deleting data, rewriting history, force-pushing.
  • Spending money or changing an account.
  • Anything that leaves the machine: a post, an email, a message.
  • New rules for the agents: they propose, I approve each one.

Never

  • Put secrets in files, commits, logs or prompts.
  • Send, post or publish without my OK.
  • Edit its own rules.

Some of these limits are scripts, such as the separate copy per task and the gate before a push. Others are written rules every agent loads. A rule is a request and a script is a lock, so I move rules into scripts when the same miss comes back.
