The full post

For readers who want the whole argument

The problem

Picture three helpers who each keep their own notebook of how you like things done. You tell the first one a rule. The second one never hears it. The third one lives in another house. That is how I used AI tools for a long time. This is my view from using them every day, not a survey.

  • Every tool keeps its own rules. Claude Code, Codex, Gemini CLI and the rest each read their own rules file from their own folder. The same rule gets written again in each one.
  • Memory stays behind. What one tool has learned about how you work does not travel to the next. Switch tool and you start again.
  • A new laptop starts blank. Move to another machine and the setup is rebuilt by hand, from memory.
  • Newcomers cannot tell which copy is right. When two copies of a rule differ, it is hard to know which one is current.

All four get easier when there is one copy of the rules and one way to rebuild the setup.

1. One map every tool loads first

What goes in the base file?

Think of the sign at the entrance of a building: it does not hold the building, it tells you which door to use. My base file is that sign. It is one AGENTS.md (the plain text rules file that many coding agents read at the start of every session) kept in my dotfiles, the folder of configuration files I carry from machine to machine.

It holds five things, and no more:

  1. House rules. The rules I want every agent to follow, such as checking before reporting and asking before anything destructive.
  2. Who does what. Which tool is for which kind of work.
  3. A routing table. For each kind of task, the folder to open and the files to read first.
  4. The tools I have. So no agent installs a second copy of one I already use.
  5. Naming. How dates, drafts and decisions are named.

Every one of these tools loads it first: Claude Code, Codex, OpenCode, Gemini CLI, Pi, DeepSeek Harness and the workers FirstMate launches. Any agent, model or machine starts from the same rules.

The file is short on purpose. A project adds its own AGENTS.md on top, and nothing in the base file is repeated there. The routing idea comes from the Interpretable Context Methodology, listed in the credits.

2. How each tool finds it

A link, not a copy

Each tool wants its rules in its own place. Rather than copy the base file into each place, the tool's folder holds a link to it. The folder keeps only that link and the tool's own settings.

LayerHolds
Base mapthe shared rules, written once
Vendor foldera link to the base map, plus that vendor's own settings
Projectits own AGENTS.md, added on top

Because the folder holds a link, there is nothing to keep in step. I change a rule in one place, and each tool reads the change the next time it starts. Adding a new tool means one link and its own settings.

3. The same setup on every machine

What does Nix do here?

A recipe gives the same dish in any kitchen. Nix does that for a computer: you write down what the machine should have, and Nix builds it. The same description gives the same setup.

Nix rebuilds the same setup on both of my Macs. So the machine does not matter: any agent, model or machine starts from the same rules and the same tools. A new machine is a rebuild, not a hand-made copy of the old one.

4. The lifetime sync warranty ;)

What is promised?

Lifetime sync warranty ;)

Valid for the lifetime of the text file. Void if someone edits a vendor folder by hand. Not transferable to a tool that never loads the file.

That is a joke, and not a promise. A text file and a Nix description can break like anything else. What I do have is one place to fix a rule, and a written description to rebuild from.

The base file shares the rules, not the settings. Each vendor's own settings stay in its own folder, and each tool still does its own work in its own way.

Why it matters

A good assistant is one you do not have to brief twice. When the rules live in one place, a new tool, a new model or a new laptop does not mean starting the briefing again.

It helps me first: I fix a rule once. It helps the AI work my way, because every agent starts from the same map. I also think it makes AI easier for newcomers: five lines in one file is a smaller first step than rules scattered across tools, and it is something you can share, for the bigger good.

5. What's next

  • A new tool gets one link and its own settings, nothing more.
  • The base file stays short. Detail goes in a project's own AGENTS.md.
  • The setup is rebuilt from the Nix description when I add a machine.

6. Try it yourself

Three steps.

  1. Write your five most repeated rules in one plain text file.
  2. Make each tool's rules file point at it with a link, so there is only one copy.
  3. Open a second tool and ask it to repeat the first rule back. If it can, the link works.
